# Pocketful: Four Agents in BAND

**Team:** signalandspark · **Track:** Pocketful · **Event:** WeAreDevelopers Hackathon

Four BAND-owned Codex agents built this wallet application through four cumulative stages. The coordinator assigned work and acceptance criteria; two builders owned the service and browser interface; an independent verifier checked committed revisions and returned reproduced defects to their owners. The stage code and verification tools retain their original per-seat commits.

Pocketful moves seeded test balances between wallets. It supports payments, requests, bill splits, authorizations, historical statements, payment corrections, refunds and atomic correction batches. It has no bank connection or real-money deposits.

## Run the app

Follow [stage-4/RUN.md](stage-4/RUN.md) for the latest application. Each earlier folder has its own `Dockerfile` and `RUN.md`. The container uses Python's standard library, includes all browser assets and needs no outbound runtime network.

The service starts empty. Initialize a disposable local instance with the fixture format in the official specification, then sign in with a seeded test account. Signup creates a zero-balance account. Funds are seeded by the test fixture; there is no top-up flow.

This is a conformance-test application. Its reset, export and import controls are deliberately unauthenticated, and state is held in memory. Run it locally or in an isolated test environment; it is not a public banking service. Exports contain test credentials and active session tokens and must remain private.

## Reproduce the official checks

Use the [official kickoff repository](https://github.com/band-ai/dark-factory-wearedevs), pinned for this run at `803560d2a678ace1414465c098eb0ab5380ffade`. Install its documented harness dependencies and run from that checkout:

```sh
python -m harness check /absolute/path/to/this-repository --track pocketful
python -m harness run --track pocketful --repo /absolute/path/to/this-repository --all --mode isolated --out /absolute/path/to/new-checks
```

Use a new output directory. The isolated run builds each stage independently with the event's resource and network limits. Follow each stage's `RUN.md` separately to inspect its behavior and browser screens.
